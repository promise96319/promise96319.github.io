### 1\. 初步评估

1. 是否应该进入到 CBB？
    1. 是否有实际的使用场景？如果不确定，可以在群里问下其他人是否有相关使用场景。
    2. 是否具有通用性能够在多处使用？
    3. 封装组件后是否能有效地提升开发效率，节省开发时间？
    4. 是否已经存在相关解决方案？
        1. 团队内部
            1. 团队内部是否已经存在相关组件？能否在已有组件基础上进行扩充？当前组件是否也应该满足这些相关组件的功能？
            2. 团队内部是否有人做过相关的调研和尝试，是否踩过相关的坑？
        2. 开源项目
            1. 是否有相关开源项目？如果有的话，为什么不直接使用这些开源项目？差异化在哪里？
            2. 有哪些地方是可以向开源项目借鉴的？
    5. 综上几点，是否有必要去封装该组件？
2. 进入到哪个位置？（[组件库](https://confluence.qingteng.cn/pages/viewpage.action?pageId=180017849)）
    1. design（是否为通用基础组件，可以参考其他开源组件库，主要侧重于提供最基础的能力及灵活的扩展性）
    2. ui（基于 design 对功能的扩充，与具体业务无关，通过再次封装为开发提供便捷性）
    3. shared（与业务相关，涉及到具体的业务逻辑）
3. 以上内容是否与相应人员同步？

### 2\. 组件定义

1. 组件支持的功能有哪些？分别在哪些场景下使用？解决了哪些问题？
2. 以上内容是否与相应人员同步？

### 3\. 设计同步

1. 是否有相应的设计规范？如果没有，是否应该出相应的设计稿和规范？
2. 设计规范是否经过设计评审和前端评审？设计和前端是否达成共识？

### 4\. 需求整理

见[交互功能整理](https://confluence.qingteng.cn/pages/viewpage.action?pageId=22578818)

### 5\. API制定

1. 其他人如何使用这个组件？使用起来是否方便？如果复杂的话可以用伪代码加以说明。
2. 内部提供给外部哪些 API ？这些 API 都是必须的吗？需要提供相应的 interface 及说明。
3. API 是否符合[API规范](https://confluence.qingteng.cn/pages/viewpage.action?pageId=163172458)？
4. 以上内容是否与相应人员同步？同步后是否达成共识？
