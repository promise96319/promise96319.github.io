### 微前端架构改造（2023.11~2024.04）

**项目背景**：
公司原有项目采用联邦模块（Module Federation）组织多个子应用，随着业务规模扩张，逐渐暴露出样式冲突、JS 运行环境冲突、应用卸载重载顺序错乱等架构瓶颈，影响开发效率与线上稳定性，急需重重构微前端架构以支撑后续业务扩展。

**职责**：
- 主导微前端技术选型与架构方案设计。
- 推动新架构方案落地，协调多业务团队顺利迁移。
- 负责架构实施过程中的兼容性适配与性能优化。

**核心技术与行动**：
- 综合评估多种微前端方案，最终基于 qiankun v3，结合公司现有系统架构特性进行定制化改造。
- 结合 Shadow DOM 和 qiankun 沙箱机制，实现子应用样式隔离与运行环境完全隔离，有效解决跨应用样式与环境冲突问题。
- 深入排查并修复各业务线在新架构下的兼容性问题，制定并实施针对性解决方案。
- 设计统一的子应用接入规范和迁移文档，降低各业务线迁移成本。

**项目成果**：
- 新架构支持子应用低成本接入，迁移流程平均可在 0.5 天内完成，有效提升扩展效率。
- 新架构稳定支撑生产环境运行一年以上，并服务 20+ 子应用，未出现架构性故障；
- 子应用开发独立性大幅提升，有效提升整体开发协同效率。

### VS Code 插件

 **项目地址**：[github](https://github.com/promise96319/snippets-manager/blob/master/README.md)

 **插件地址**：[vscode](https://marketplace.visualstudio.com/items?itemName=promise96319.snippets-manager)

 **开发背景**：
由于平时开发中存在大量相同或者类似的代码，比如通用的业务组件代码结构，比较繁琐的代码片段等等。每次寻找代码、copy、修改，一套流程下来，浪费了许多时间。如果用 `cli` 生成模板的话，修改和维护成本也比较高，有点舍本逐末。幸好 `VS Code` 自带代码片段功能，但是 `VS Code` 自带的代码片段属实有点难以编辑，也比较难以管理。找了相关的插件，发现都不大合心意，所以花了一个周末开发了这款插件。主要解决了我认为比较重要的两点问题：

- 编辑方便：直接选取源代码作为模板，更改自己需要替换的区域即可，比直接编写代码片段结构方便多了。
- 管理方便：代码片段能进行分组，根据不同的业务，不同的项目，或者不同的语言等来进行分组，便于管理。
